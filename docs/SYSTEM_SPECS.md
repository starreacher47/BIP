# Описание системы

## Назначение

**Token Security Auditor** — учебная система для обнаружения проблем, связанных с токенами и сессионными идентификаторами в HTTP(S)-трафике.

Система перехватывает трафик, извлекает признаки запросов и ответов, применяет специализированные правила безопасности и формирует результаты аудита.

Основные обнаруживаемые сценарии:

* передача токена через URL;
* небезопасные параметры session cookie;
* повторное использование токена разными клиентами;
* использование истёкшего токена;
* изменение географической метки;
* session hijacking;
* session fixation.

Система предназначена для учебных и демонстрационных целей и не является заменой промышленным DAST, SIEM или WAF.

---

## Основные компоненты

### Auditor

Flask-приложение, предоставляющее:

* веб-интерфейс и административную панель;
* REST API;
* аутентификацию и авторизацию;
* управление пользователями и сессиями;
* API-ключи;
* хранение результатов аудита;
* метрики Prometheus.

Основное хранилище текущего стенда — SQLite.

### mitmproxy и analyzer

mitmproxy принимает внешний HTTPS-трафик на порту `443` и передаёт его лабораторному `target`.

Analyzer addon обрабатывает полученные HTTP-потоки и передаёт данные аудита в Auditor API.

### Target

Отдельное лабораторное HTTPS-приложение, предназначенное для воспроизведения контролируемых безопасных и небезопасных сценариев.

### Attack Simulator

Учебный симулятор для воспроизведения контролируемых сценариев, включая session hijacking, session fixation и повторное использование токенов.

### Мониторинг

Для мониторинга используются:

* **Prometheus** — сбор метрик;
* **node-exporter** — системные метрики;
* **Grafana** — визуализация.

## Архитектура

Основной поток аудита:

```text
Client / Attack Simulator
          │
          │ HTTPS :443
          ▼
      mitmproxy
          │
          ▼
        target
          │
          ▼
    analyzer addon
          │
          ▼
     Auditor API
          │
          ▼
        SQLite
```

Мониторинг:

```text
Auditor ───────────► Prometheus ─────► Grafana
                         ▲
                         │
node-exporter ──────────┘
```

Основные контейнеры подключены к Docker-сети `lab`.

## Анализ трафика

Для аудита используются признаки HTTP-запросов и ответов, включая:

* метод и URL;
* host и path;
* IP клиента;
* User-Agent;
* HTTP-заголовки;
* cookies;
* query parameters;
* параметры тела запроса;
* HTTP status code;
* метку `X-Country`.

На основании этих данных Auditor применяет правила безопасности и формирует findings с категорией, уровнем риска и рекомендацией.

`X-Country` используется только как лабораторный признак географии и не является механизмом определения реального местоположения пользователя.

---

## Роли

В приложении предусмотрены основные роли:

* `user` — работа с собственными данными и доступными функциями;
* `admin` — расширенный доступ к административным функциям;
* `superuser` — расширенные полномочия управления системой.

---

## Хранение данных

Auditor использует SQLite в Docker volume:

```text
app_data
```

Grafana использует отдельный volume:

```text
grafana_data
```

Такое разделение позволяет сохранять состояние приложений независимо друг от друга.

---

## Ограничения

Система предназначена для локального учебного стенда. Основные ограничения:

* SQLite не рассчитан на высокую производственную нагрузку;
* `target` содержит намеренно уязвимые сценарии;
* TLS-сертификаты предназначены для локальной среды;
* географический анализ основан на переданной клиентом метке;
* Attack Simulator должен использоваться только с разрешёнными целями;
* система не является полноценной заменой DAST, SIEM или WAF.

Nginx, Keycloak и MinIO не являются обязательными компонентами текущей рабочей архитектуры.
