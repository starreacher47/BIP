# Руководство пользователя

## 1. Вход

Auditor доступен по адресу:

```text id="q1m6ty"
https://127.0.0.1:5000
```

Пользователь может зарегистрироваться, войти в систему и, при включённой функции, использовать TOTP 2FA.

В профиле также доступны управление собственными сессиями и их отзыв.

---

## 2. Аудит трафика

Основной сценарий работы — анализ HTTPS-трафика через mitmproxy.

Клиент или Attack Simulator отправляет запросы через:

```text id="m4a9fj"
https://127.0.0.1:443
```

Трафик проходит через mitmproxy и лабораторное приложение `target`. Analyzer addon передаёт данные события в Auditor, где они сохраняются и проверяются правилами безопасности.

---

## 3. Лабораторное target-приложение

`target` предназначен для воспроизведения контролируемых безопасных и небезопасных сценариев.

В частности, доступны сценарии:

* токен в URL;
* небезопасные cookie;
* `Authorization` header;
* session fixation;
* защищённый ресурс;
* logout.

Приложение является частью Docker-стенда и отдельно запускать его не требуется.

---

## 4. Attack Simulator

Симулятор находится в:

```text id="z7h2qs"
analyzer/attack_simulator.py
```

Он используется для воспроизведения контролируемых сценариев, включая:

* session hijacking;
* session fixation;
* повторное использование токена;
* использование истёкшего токена;
* изменение географической метки.

Симулятор предназначен только для локальных или явно разрешённых целей.

---

## 5. Результаты аудита

Результаты обнаружения доступны в интерфейсе Auditor.

Для finding могут отображаться:

* категория;
* уровень риска;
* тип нарушения;
* связанные признаки события;
* рекомендация по устранению.

Чувствительные значения токенов могут отображаться в виде fingerprint или ограниченного preview.

Основные правила аудита:

| Правило               | Назначение                               |
| --------------------- | ---------------------------------------- |
| `TOKEN_IN_URL`        | Токен в URL                              |
| `COOKIE_NO_SECURE`    | Cookie без `Secure`                      |
| `COOKIE_NO_HTTPONLY`  | Cookie без `HttpOnly`                    |
| `COOKIE_NO_SAMESITE`  | Cookie без `SameSite`                    |
| `TOKEN_MULTI_CLIENT`  | Токен используется разными клиентами     |
| `EXPIRED_TOKEN_REUSE` | Повторное использование истёкшего токена |
| `GEO_CHANGE`          | Изменение географической метки           |
| `SESSION_HIJACKING`   | Session hijacking                        |
| `SESSION_FIXATION`    | Session fixation                         |

`TOKEN_OVER_HTTP` относится к обычному HTTP-трафику и не демонстрируется в основной HTTPS-конфигурации стенда без отдельного изменения target.

---

## 6. API

Auditor предоставляет REST API с префиксом:

```text id="4cqv7z"
/api/v1
```

Для защищённых API-запросов используются API-ключи.

Addon mitmproxy передаёт события аудита через:

```text id="u6g5pc"
POST /api/v1/audit/captures
```

Администратор может управлять API-ключами через административный интерфейс.

---

## 7. Мониторинг

Для мониторинга используются Prometheus и Grafana.

Prometheus:

```text id="gqj9kp"
http://127.0.0.1:9090
```

Grafana:

```text id="p8m3vx"
http://127.0.0.1:3000
```

Dashboard отображает основные показатели работы стенда, включая CPU, RAM, HTTP-запросы и HTTP 429.

---

## 8. Безопасность использования

Лабораторные уязвимые endpoints и Attack Simulator предназначены только для тестовой среды.

Не следует направлять тесты на сторонние системы без явного разрешения.

Локальные сертификаты, тестовые секреты и другие значения лабораторного окружения не предназначены для production.
